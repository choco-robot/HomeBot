## 一、项目概述

### 1.1 项目目标
基于 HomeBot 开发一款**远程打麻将机器人**，解决线下麻将"三缺一"的问题。核心功能包括：

1. **远程出牌**：用户通过 Web 页面观看牌桌画面，点击虚拟手牌完成出牌，由机械臂自动抓取并打出目标牌
2. **双向音视频**：用户与现场其他玩家通过腾讯云 TRTC 进行实时语音视频通话
3. **自动牌面识别**：使用 YOLO 模型实时识别 34 种国标麻将牌面

### 1.2 硬件环境
- **主机**：Windows PC（运行 HomeBot 控制系统）
- **摄像头**：2 个 USB 摄像头
  - `device_id=0`：顶置摄像头（俯视牌桌）→ 显示给用户看牌桌
  - `device_id=1`：前置摄像头（拍摄手牌）→ YOLO 检测输入
- **机械臂**：HomeBot 5DOF 机械臂 + 夹爪 + 升降平台
- **音频设备**：笔记本内置麦克风 + 外接音箱

> **架构说明**：前置摄像头专门用于 YOLO 手牌检测，顶置摄像头用于向用户展示牌桌全局画面。这种分离设计避免了单摄像头同时承担检测和显示任务时的视角冲突问题。

## 二、系统架构

### 2.1 总体架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           远程云服务器                                        │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  mahjong_bot/web_server.py  (Flask + SocketIO)                        │  │
│  │  - 提供 mahjong.html 给玩家访问                                       │  │
│  │  - /api/trtc/usersig (为 player 生成 UserSig)                         │  │
│  │  - SocketIO ↔ MQTT 桥接                                              │  │
│  │    * 收到前端事件 → MQTT publish 到 command topic                     │  │
│  │    * 收到 MQTT status → SocketIO broadcast 给前端                     │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │ MQTT
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                      机器人本地 (HomeBot Windows PC)                         │
│  ┌──────────────────────┐    ┌─────────────────────────────────────────┐   │
│  │ robot_bridge_server  │    │  robot_trtc.html (Chrome Kiosk)         │   │
│  │ - MQTT 客户端         │    │  - 顶置摄像头 → TRTC 主路（牌桌视角）   │   │
│  │   * 订阅远程指令       │◄──►│  - 麦克风音频 → TRTC 音频               │   │
│  │   * 发布检测/状态      │    │  - 订阅远端音频 → 音箱播放              │   │
│  │ - ZMQ 客户端          │    │  - 以 robot 身份加入房间                │   │
│  │   * 前置视频流（YOLO） │    └─────────────────────────────────────────┘   │
│  │   * 机械臂服务         │                                                  │
│  │ - YOLO 检测循环        │                                                  │
│  │ - 机械臂动作执行       │                                                  │
│  └──────────────────────┘                                                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

**架构说明（v1.3 调整后）**：
- **远程云服务器**：部署 `web_server.py`，玩家通过浏览器访问。不再直接连接本地 ZMQ 视频流，所有控制指令和状态通过 MQTT 中转。
- **机器人本地端**：运行 `robot_bridge_server.py`，作为 ZMQ（前置视频/机械臂）和 MQTT（远程服务器）之间的桥接。
- **音视频**：机器人仅通过 TRTC 推送**顶置摄像头**一路视频（牌桌俯瞰）；前置摄像头**仅用于本地 YOLO 检测**，不参与 TRTC 推流。

### 2.2 通信协议

| 链路 | 协议 | 端口/地址 | 用途 |
|------|------|----------|------|
| 前置视频流 | ZeroMQ PUB → YOLO 检测 | `tcp://*:5562` | 手牌检测（YOLO 推理输入） |
| 机械臂控制 | ZeroMQ REP | `tcp://*:5557` | 动作执行 |
| 实时指令 | WebSocket (SocketIO) | `:5100` | 选牌、出牌、调试（前端 ↔ 云服务器） |
| 控制/状态 | MQTT | `homebot/mahjong/command` + `homebot/mahjong/status` | 云服务器 ↔ 机器人本地桥接 |
| 音视频通话 | 腾讯云 TRTC Web SDK | 云端 | 双向语音视频（机器人推顶置摄像头） |

## 三、技术路线

### 3.1 视觉系统
- **检测模型**：YOLOv8 / YOLO11 / YOLO26 nano（复用现有 Ultralytics 架构）
- **检测目标**：34 种国标麻将 + 牌背
- **推理框架**：`ultralytics` + OpenCV
- **输出处理**：检测结果按 x 坐标排序，映射为手牌列表
- **坐标转换**：四点透视标定（Homography 矩阵）→ 图像坐标转机械臂底座坐标

### 3.2 机械臂动作规划
定义标准动作原语：

| 动作 | 说明 |
|------|------|
| `move_to_hover(x, y, z)` | 移动到目标牌正上方安全高度 |
| `descend_and_grasp()` | 下降并夹爪闭合抓取 |
| `lift_and_move_to_slot()` | 提起并移动至出牌槽上方 |
| `release_or_push()` | 松开夹爪/侧推出牌 |
| `return_to_rest()` | 回到休息位 |

### 3.3 音视频方案（腾讯云 TRTC）
- **一房间多角色**：远程用户（player）、机器人终端（robot）、现场玩家
- **机器人端**：本地 Chrome 页面 `robot_trtc.html` 仅推**一路视频**
  - 顶置摄像头（主路视频 + 音频）→ 牌桌俯瞰视角
  - 前置摄像头**不推流**，仅由本地 `robot_bridge_server.py` 用于 YOLO 检测
- **Web 端**：用户页面嵌入 TRTC Web SDK，订阅机器人顶置视频流并发布自己的音视频
- **音频播放**：远端音频通过 Chrome 默认音频设备（音箱）输出

## 六、配置说明

### 6.1 环境变量（`.env.local`）

在 `software/.env.local` 中添加：

```ini
# 腾讯云 TRTC（必填）
TRTC_SECRET_KEY=你的_腾讯云_SecretKey

# 可选：现有 TTS / LLM 配置
VOLCANO_APPID=your_appid
VOLCANO_ACCESS_TOKEN=your_token
ARK_API_KEY=your_api_key
ARK_MODEL_ID=ep-your_model_id
```

### 6.2 TRTC 前端配置

修改 `software/src/applications/mahjong_bot/static/robot_trtc.html` 顶部：

```javascript
const SDKAPPID = 你的_SDKAppID;
const SECRETKEY = '你的_SecretKey';  // 仅本地测试用
const ROOMID = 'mahjong_room_001';
const USERID = 'robot';
```

> **安全提示**：生产环境中 `SecretKey` 不应硬编码在前端，应统一调用后端的 `/api/trtc/usersig` 接口生成 UserSig。

## 八、关键风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| **机械臂精度不足** | 抓取失败 | 使用固定手牌架（预定位），将自由抓取降级为"格子到格子"的搬运 |
| **牌面遮挡/倒立** | 检测失败 | 手牌架设计倾斜角度（15°-30°），确保牌面朝向摄像头 |
| **光照变化** | 检测抖动 | 顶置摄像头加装环形补光灯，统一光照环境 |
| **模型推理延迟** | 实时性差 | 使用 YOLOv8n，推理尺寸 320/416，目标 >15 FPS |
| **TRTC 推流失败** | 无法音视频通话 | 优先使用 Chrome 浏览器测试，确认摄像头权限已授权 |
| **双摄像头序号混乱** | 画面错位 | 通过 OpenCV 逐一测试 `VideoCapture(0/1)`，在配置中固定映射 |
| **MQTT Broker 不可达** | 云-端通信中断 | 确保云服务器和机器人都能访问同一个 MQTT broker；测试阶段可用公共 broker（如 `broker.emqx.io`） |
| **顶置摄像头被占用** | TRTC 无法推流 | 顶置摄像头仅由 Chrome 使用，前置仅由 OpenCV 使用，避免同一摄像头被两个进程同时打开 |
