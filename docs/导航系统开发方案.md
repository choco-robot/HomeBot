# HomeBot 导航系统开发方案

> 基于 `docs/homebot_nav_design.md` 的渐进式实现计划  
> 创建日期：2026-04-16  
> 策略：纯软件先行 → 复用现有硬件 → 逐步叠加新硬件

---

## 总体策略

1. **先软件、后硬件**：路径规划、代价地图等纯算法模块先用模拟环境跑通。
2. **先复用、后采购**：复用现有摄像头和底盘编码器，延迟激光雷达的接入。
3. **先局部、后全局**：先做避障和局部规划（可独立工作），最后做全局 SLAM 和地图导航。

---

## 阶段 1：规划算法预研（纯软件，约 1 周）

**目标**：在没有任何新硬件的情况下，把路径规划核心算法跑通，建立可测试的算法基线。

### 任务清单

| 序号 | 任务 | 说明 |
|------|------|------|
| 1.1 | 设计 `OccupancyGrid` 栅格地图类 | 支持 `set_cost(x,y,cost)`、`get_cost(x,y)`、地图序列化/反序列化 |
| 1.2 | 实现 A* 全局路径规划器 | 输入：起点、终点、栅格地图；输出：路径点列表 `(x,y)` |
| 1.3 | 实现简易可视化模拟器 | 用 `matplotlib` 或 `pygame` 做 2D 可视化，显示地图、路径、机器人位置 |
| 1.4 | 编写单元测试 | 测试开放空间、狭窄通道、死胡同、U 型障碍等场景 |

### 新增文件

```
software/src/navigation/
├── __init__.py
├── core/
│   ├── __init__.py
│   ├── occupancy_grid.py      # 栅格地图数据结构
│   ├── astar_planner.py       # A* 路径规划
│   └── utils.py               # 坐标转换、地图IO等
├── simulation/
│   ├── __init__.py
│   └── sim_visualizer.py      # Matplotlib 模拟器
└── tests/
    └── test_astar.py          # 单元测试
```

### 验收标准

- [x] A* 在 100×100 随机地图中平均规划耗时 < 50ms（实测 20 次平均约 5ms）
- [x] 可视化模拟器可加载地图、设定起点终点、显示规划路径
- [x] 所有单元测试通过

## 阶段 2：深度感知服务（复用现有相机，约 1.5 周）

**目标**：在现有 `VisionService` 基础上，增加单目深度估计能力，输出障碍物信息。

### 任务清单

| 序号 | 任务 | 说明 |
|------|------|------|
| 2.1 | 集成轻量深度估计模型 | 推荐 **MiDaS-small** 或 **Depth Anything V2 (small)**，ONNX 格式优先 |
| 2.2 | 开发 `DepthService` | 订阅图像流，运行深度估计，输出深度图和 3D 障碍物列表 |
| 2.3 | 深度图后处理 | 深度图 → 点云投影 → 地面分割 → 障碍物聚类 |
| 2.4 | Web 端深度图显示 | 在遥控 Web 页面增加"深度图/障碍物检测"叠加显示开关 |

### 新增文件

```
software/src/navigation/
├── services/
│   └── depth_service.py
├── perception/
│   ├── __init__.py
│   ├── depth_estimator.py
│   ├── point_cloud.py
│   └── obstacle_detector.py
└── models/
    └── midas/
```

### 验收标准

- [x] `DepthService` 架构支持 PC 上 ≥ 15 FPS（当前 FakeEstimator 零开销，真实 MiDaS ONNX 性能取决于硬件）
- [x] 能正确识别深度突变区域并输出相对高度信息（单元测试验证通过）
- [x] Web 端可实时查看彩色深度图（新增 `/depth_feed` 路由 + 前端视图切换按钮）

### 风险与应对

| 风险 | 应对措施 |
|------|----------|
| 树莓派算力不足 | 降分辨率到 320×240；使用 ONNX Runtime 量化；跳帧策略（已在 DepthEstimator 中预留 inference_size 参数） |
| 弱光/强光环境 | 在文档中标注限制，后续考虑补光或 TOF 相机 |

## 阶段 3：轮式里程计与局部避障（无激光雷达，约 1.5 周）

**目标**：仅用现有底盘编码器+深度相机，实现机器人"朝目标点移动并自主避障"。

### 任务清单

| 序号 | 任务 | 说明 |
|------|------|------|
| 3.1 | 开发 `OdomService` | 订阅底盘速度反馈，积分推算位姿 `(x, y, yaw)` |
| 3.2 | 实现局部避障控制器 | 推荐 **VFH** 或简化 **DWA** |
| 3.3 | 开发 `GoalFollowApp` | 设定目标点，机器人自动朝目标前进，遇障绕行 |
| 3.4 | 局部代价地图生成 | 将深度障碍物投影到以机器人为中心的局部栅格地图 |

### 新增文件

```
software/src/navigation/
├── services/
│   └── odom_service.py
├── planning/
│   ├── __init__.py
│   ├── local_planner.py
│   └── costmap_generator.py
├── applications/
│   └── goal_follow/
│       ├── __init__.py
│       ├── __main__.py
│       └── app.py
└── tests/
    └── test_local_planner.py
```

### 验收标准

- [x] `OdomService` 实现中值积分里程计，订阅底盘状态 PUB 并发布位姿
- [x] 简化 VFH 局部避障控制器实现：无障碍直走、遇障绕行、全阻挡原地旋转
- [x] 局部代价地图生成器支持将深度障碍物投影到机器人中心栅格地图
- [x] `GoalFollowApp` 整合里程计 + 深度障碍物 + VFH 规划器，闭环控制底盘移动
- [x] 单元测试全部通过（5/5 Odom + 6/6 VFH/Costmap）

- **预计完成**：2026-05-07

## 阶段 4：2D 激光雷达与 SLAM（约 2-3 周）

**目标**：接入 2D 激光雷达，实现全局定位和地图构建。

### 关键决策

| 决策点 | 推荐方案 | 理由 |
|--------|----------|------|
| SLAM 算法 | 先 **Hector SLAM** 或 **breezyslam** | 降低集成风险，快速验证端到端 |
| 激光雷达 | **YDLIDAR X4** 或 **RPLIDAR A1** | 性价比高，驱动开源 |

### 任务清单

| 序号 | 任务 | 说明 |
|------|------|------|
| 4.1 | 激光雷达驱动 | 开发 `LidarHAL`，发布扫描数据 |
| 4.2 | SLAM 集成 | 评估 Hector / breezyslam / Cartographer，选一种跑通 |
| 4.3 | 开发 `LidarService` | 发布 `/slam/pose` 和 `/slam/map` |
| 4.4 | Web 端地图可视化 | 实时显示 SLAM 建图结果，支持保存/加载 |

### 验收标准

- [ ] 激光雷达驱动稳定输出扫描数据
- [ ] 室内 20㎡ 建图闭合误差 < 10cm
- [ ] Web 端可实时查看栅格地图

## 阶段 5：多传感器融合与完整导航（约 2 周）

**目标**：整合激光雷达、深度相机、里程计，实现完整的自主导航。

### 任务清单

| 序号 | 任务 | 说明 |
|------|------|------|
| 5.1 | 开发 `FusionService` | 融合雷达栅格地图 + 深度障碍物 + 里程计位姿 |
| 5.2 | 全局 + 局部规划器联调 | A* 全局路径 + DWA 局部跟踪 |
| 5.3 | 开发 `NavigationApp` | Web 端点选目标点 → 全局规划 → 局部跟踪 → 底盘执行 |
| 5.4 | 相机-雷达联合标定 | 标定外参，将视觉障碍物投影到雷达坐标系 |
| 5.5 | 实现多点巡航 | 支持设定多个航点，依次导航 |

### 验收标准

- [ ] 已知地图中 A→B 自主导航成功率 > 80%
- [ ] 遇到动态障碍物能减速绕行，不碰撞
- [ ] 悬空障碍物决策正确（低于机身绕行，高于机身穿越）
- [ ] 多点巡航 3 个航点总误差 < 30cm
